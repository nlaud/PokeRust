- Tests that just randomly click moves with random teams for like 50ish battles to search for inference contraditions, which should be impossible when taking from real data.
  - **[2026-07-11]** Exactly this kind of fuzzing (scripted battles against the real running server, not synthetic unit tests) is what found and confirmed four more inference bugs beyond S34/S35, all now fixed:
    - **S36**: `pass4_speed_from_order`'s per-mover Tailwind snapshot used each mon's OWN "as of just before its move" time — wrong for a same-side pair where the earlier mover's move IS the Tailwind cast (e.g. Aerodactyl casts Tailwind, its own teammate acts next): the teammate's snapshot correctly shows Tailwind up, but that boost must not be backed into the pairing against the CASTER, which raced before Tailwind existed. Now uses the temporally-earlier mover's snapshot for both sides of every pairing.
    - **S37 (the big one)**: `pass1_switch` processed P1's own team-preview "sent out" `SimultaneousSwitch` exactly like a genuine mid-battle switch — looking it up in the (bench-only) known/possible-back lists, failing, and rebuilding P1's own fully-known lead as a wide-uncertain opponent-style mon (`nature=Not([])`, `EVs=[0,252]`). This corrupted P1's OWN belief on every real battle from turn 1, invisibly in most cases (a single hit's inference just came out imprecise) but visibly once a mega-evolved/multi-hit turn made the corruption collide with itself. Root cause of most of the remaining "every candidate nature is infeasible" and `SpeedComparison` contradictions.
    - Verified via 90+ scripted turns through the real HTTP API (singles, doubles, and a Mega Evolution + Tailwind + doubles-spread scenario matching a real report) — 0 failures after, vs 100% failure on the Mega scenario before. Regression tests: `test_s34_s35_*`, `test_s37_p1_own_lead_stays_known_through_team_preview_transition` in `inference_tests.rs`.
    - **S38**: `run_pass5_all_mons` re-ran `pass5_back_solve`'s EV/IV/nature search on the OBSERVER's OWN already-fully-known mons too (not just the opponent's), because the "has known species" gate is true for both. For P1's own mons, `min_pre_nature_stat`/`max_pre_nature_stat` are deliberately left unbounded (`from_known_pokemon` sets `[0;6]`/`[u16::MAX;6]`, since those bounds are documented as "never used to constrain own mons"). Pass 5's EV-lattice search for an EXACT stat target can land on a genuine *range* of EVs that floor-round to the same integer stat — and that range is base-stat-dependent, so it differs between pre-Mega and post-Mega Tyranitar. Since pass5's writes are monotone-tightening only, and `apply_information` runs once at the team-preview transition (pre-Mega) and again the turn Mega Evolution happens (post-Mega), the two calls' pass5 runs computed two disjoint EV ranges for the SAME real EV value, inverting `minEvs > maxEvs`. Fix: skip pass5 entirely for any mon whose EVs are already fully pinned (`minEvs == maxEvs` on every stat) — nothing to back-solve. Dropped the repro's failure rate from 100% (25/25) to ~5% (3/60).
    - **S39 (the actual remaining cause of the ~5% residual)**: `pass3_damage_to_stats`'s per-hit crit detection assumed the simulator emits `Crit{target}` as a flat SIBLING immediately before its `DamageDealt` reaction, and tracked it with a `pending_crit` flag scanning `event.reactions`. The real simulator (`simulator/mod.rs`, `with_reactions(bs, EventKind::DamageDealt{...}, run_damage_reactions)`) emits `Crit` as a REACTION (child) of `DamageDealt`, not a preceding sibling — the same shape a player sees in-game ("A critical hit!" attached to that hit's own damage line). Because `event.reactions` (the flat per-move list) never contains a bare `Crit`, `pending_crit` could never be set — `is_crit` was unconditionally `false` for every hit, on every turn, since the feature existed. Direction A/B's oracle then searched only non-crit damage rolls for hits that were actually crits, computing a stat window that EXCLUDES the true value whenever the crit multiplier was needed to explain the observed damage — exactly the Rock Slide crit into Corviknight that produced the residual "every candidate nature is infeasible for stat 2" contradictions. Fixed by reading the nested `Crit` from each `DamageDealt` node's own `.reactions` instead of a sibling scan. Two hand-built regression tests (`test_pass3_dir_b_crit_observed_no_contradiction`, `test_s23_multihit_mixed_crit_keeps_true_atk_feasible`) had baked in the same wrong (sibling) event shape and were updated to match reality. 0/60 lycanroc-tyranitar failures after this fix (previously 3/60 after S38 alone).
    - A real automated fuzz harness (create battle → random legal commands → assert no panic, looped N times) is still worth building — this session's fuzzing was ad hoc (hand-written repro scripts, not committed) and every bug found required manual reproduction + bisection. Suggest a `#[test]` (or standalone binary) that: picks 2 random teamsheets, random format, random `informationMode`, then for N turns picks a uniformly-random legal command per slot from `get_possible_commands_for_active_slot`, running the belief through `apply_information` each turn — catching regressions here automatically instead of relying on a user hitting them live.
